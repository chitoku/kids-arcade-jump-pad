# Jump Pad：2026年10月16日の変更・実機確認

本書は現行実装と、このチャットで操作者が報告した結果・取得ログをまとめたものです。ログのファイル名はUTCのため10月17日ですが、試験日は米国太平洋時間の10月16日です。

## 現在実機に入っている構成

- 原型M5Stack AtomS3（MAC `dc:54:75:cb:c7:d0`）。LCDは180度回転。
- ビルド環境：**`atoms3-serial`（USB Serial専用、HID記述子・Space送信なし）**。
- Adafruit NAU7802、チャンネルA（ライブラリ指定は`0`）、ゲイン128、80 SPS、励起3.0 V。320 SPSは未試験。
- 実測速度は概ね80〜80.5 SPS。ゲーム側のConnect Serialで接続し、`EVENT,JUMP`を1P入力に使用。
- 重量校正：板約2 kgを載せた状態でtareし、追加1 kgで校正。保存値は **22687.601562 counts/kg**。この値は当該実機の値で、別個体には流用しない。
- 実機に保存された判定設定：`enter=8 / leave=3 / air=2 / land=5 kg`、`standing=500 / air=20 / landing=60 ms`。ソースの既定値とは一部異なる。

## 配線と操作

| 線 | AtomS3 | HX711 | NAU7802 |
|---|---|---|---|
| 赤 | 3V3 | VCC | VIN |
| 黒 | GND | GND | GND |
| オレンジ | G5 | DT / DOUT | SDA |
| 黄 | G6 | SCK | SCL |

ロードセル側はE+ / E− / A+ / A−を同名端子へ接続。NAU7802のB+ / B−、AV、DRDYは未接続。最終的なI²C割り当ては**G5/G6**。途中のG6/G7指定は実配線とずれていたため変更済み。両ADCは電源OFFで差し替え、同時接続しない。

- **画面短押しして離す：tare**。板は載せたまま、人・追加の重りを降ろして実行し、約2.5秒のTARE表示が終わるまで無荷重を維持する。
- **画面2秒長押し：ADC切り替え**。選択を保存して再起動。長押し途中ではtareしない。
- 最大重量の消去：Serialの`max reset`。画面短押しはMAX消去に使用しない。
- ADC選択と重量校正値はNVSに保存。HX711とNAU7802の校正値は別管理。旧HX711の`scale`値は`scale-hx`へ移行。
- ゼロ点は起動時または明示的なtareで決める。測定異常からの復帰時には再設定しない。

[写真ベースのケーブル図](atoms3-hx711-cable.png) / [編集用SVG](atoms3-hx711-cable.svg) / [詳細配線](wiring.md)。裏面シールの位置がずれて見えるため、ソケット位置とGPIO番号の対応を確認する。

## 実装した対策

1. HX711とNAU7802の読み取り切り替え、ADC別の校正保存、LCDのADC名表示。
2. NAU7802のA/B番号誤りを修正。I²C初期化の明示的な解放・再開始、起動時NACKへの有限回再試行、段階別診断、`adc scan`を追加。内部校正の待機にも期限を設定。
3. USB送信を完全な行単位の有限キューに変更。CDCの空き容量以下だけ送信し、受信側が遅い時は過剰なテレメトリを破棄。切断後に古い出力を再送しない。既存ArduinoのCDC書き込みはTXタイムアウト0でも満杯時に回り続け得た。
4. UNWEIGHTINGが450 msでタイムアウトしても、荷重がenterKg以上なら現在荷重を基準にSTANDINGへ戻す。「空」へ戻って500 msの静止を待ち直すことによる連続ジャンプ抜けを軽減。
5. ADC上下限（負側は−8,388,607を含む）と、校正済みで**−5 kg未満**の測定を無効化。無効値をジャンプ判定とMAXへ渡さず、DATAのkg=`nan`、ready=`0`として生値は残す。
6. 異常後は正常範囲の値が200 ms続いてから再開。荷重が残っていれば現在荷重で再待機し、復帰そのものではJUMPを発行しない。`SAMPLE_REJECTED` / `SAMPLE_RECOVERED`を出力。
7. センサー異常・タイムアウトでも確立済みゼロ点を保持し、荷重中の自動tareによる−5 kgのずれを防止。
8. 画面短押しをMAXリセットからtareへ変更。

| **画面短押しtare** | **最終書き込み後、操作者がTARE実行とほぼ0 kgへの復帰を確認。** |

## ログに基づく未解決事項

- 右前への大荷重で負方向の異常が繰り返し再現した。セル損傷は疑いであり、故障箇所の確定・交換試験・HX711での同一大荷重比較は未実施。
- 約−200〜−366 kg相当の生値は実際に記録された。4セルの合成ブリッジを1チャンネルで読むため、ソフトだけで異常セルを取り除いた正しい重量を復元できない。
- −5 kgガードは異常値を使った誤判定を減らす暫定策。欠測中のジャンプを復元できず、正方向の異常や−5 kg以上のずれも除去しない。機械的損傷や再発を防止する機能ではない。
- 長時間使用後のゼロ点ずれは観察されている。無荷重で短押しtareを行う運用で対応。長期ドリフト量の保証はない。
- Serial専用版の長時間連続稼働、HID版の切断再現条件、320 SPSは未検証。

## ビルド・書き込み

```sh
pio run -e atoms3-serial
pio device list
pio run -e atoms3-serial -t upload --upload-port <確認したポート>
```

書き込めなければ、画面ではなく側面リセットを約2秒長押しし、緑LEDを確認して離す。書き込みモードでポート名が変わる。書き込み後は板だけを載せてリセットを短く1回押し、自動ゼロ調整を待つ。macOSのUSB接続許可が出たらAllow。ゲームとTerminal Monitorは同じSerialポートを同時に開かない。

既定の`atoms3`はHID＋Serial版のままなので、今回の運用は**明示的に`atoms3-serial`を選ぶ**。

ホスト回帰テスト：

```sh
for source in test/*_test.cpp; do
  target="/tmp/jump-pad-$(basename "$source" .cpp)"
  c++ -std=c++17 -Iinclude "$source" -o "$target" && "$target" || exit 1
done
```
